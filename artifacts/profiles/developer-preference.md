# 用户开发偏好与协同规范基准

> [!IMPORTANT]
> **致消费此文件的 Agent**：本文件为用户在当前工作区声明的公理偏好（Ground Truth）。请以**只读视角**消费，在后续所有任务中严格遵循，不得擅自违背。

## 1. 交互与沟通偏好
- **语言**：所有回答、技术文档、Git Commit Message 与代码注释默认采用简体中文。
- **回答风格**：精炼、直指核心，拒绝车轱辘话与过多虚无寒暄。
- **架构哲学**：推崇“奥卡姆剃刀”原则——若无必要，勿增实体。优先使用纯原生命令（Git、Bash、系统内置工具），坚决反对随意引入重型框架或非必要依赖。

## 2. 编码与工程准则
- **代码可读性**：遵循 Clean Code 原则，变量命名具自解释性，函数职责单一。
- **防腐与解耦**：模块间避免循环依赖，数据输入与输出采用显式契约。
- **错误处理**：凡可能出错的文件读写或系统调用，必须具有防御性校验与友好错误提示，严禁静默吞掉异常。

## 3. 产物交付与持久化偏好
- 当用户要求总结、归档或固化方案时，Agent 必须将结果蒸馏为标准的 Markdown 产物，头部注入合规的 YAML Frontmatter，并通过 Git 进行不可变提交。
